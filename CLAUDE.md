# Magpie / Сорока — голосовой помощник

Личное Android-приложение для быстрого голосового ввода: напоминания, приём
таблеток, список покупок. Главная ценность — **скорость вызова**: тап по
виджету/плитке → сразу микрофон, без промежуточных экранов.

Статус: **план утверждается, код не начат.**

---

## 1. Контекст проекта

- **Пользователь:** один основной, устройство Pixel 8 (свежий Android).
  Возможна раздача APK членам семьи — у каждого свои данные, обмена между
  устройствами нет.
- **Уровень владельца:** уверенное программирование, Android/Kotlin — с нуля.
  В обсуждениях подробно объяснять Android-специфику (жизненные циклы,
  разрешения, ограничения фона); базовое программирование объяснять не нужно.
- **Сборка:** Android Studio локально + GitHub Actions (debug-APK артефактом).
- **Публикации в Google Play нет**, установка APK напрямую.

### Явно вне области проекта

Свой бэкенд · синхронизация между устройствами · двусторонняя синхронизация с
Google · Wear OS и смарт-браслеты · Google Calendar · аналитика и
краш-репортинг · учёт остатка таблеток · офлайн-распознавание речи.

## 2. Требования

### Общее
- Локальная БД — единственный источник правды.
- Интерфейс на русском и английском (`values-ru/` + `values/`).
- Тип записи определяется **точкой входа**, а не содержанием фразы:
  виджет покупок → покупка, вход напоминаний → напоминание. Автоматической
  классификации нет.
- Распознавание речи — только онлайн, системное (`RecognizerIntent`).
  Без сети функция голоса недоступна, это ожидаемое поведение.
- **Разрешение `RECORD_AUDIO` приложению не нужно** и не объявляется: при
  запуске `RecognizerIntent` записывает приложение-распознаватель в своём
  процессе. Разрешение потребуется только при переходе на `SpeechRecognizer`
  с собственным интерфейсом. В манифесте вместо этого нужен блок `<queries>`
  с `android.speech.RecognitionService` — иначе на Android 11+ распознаватель
  не виден и запуск падает.
- После распознавания — экран подтверждения с редактируемыми полями.
  (Возможное упрощение в будущем: карточка на 3 секунды с автозакрытием.)

### Напоминания
- Одноразовые («завтра в 9 позвонить в поликлинику») и повторяющиеся
  («каждый вторник вынести мусор»).
- Событий с длительностью нет — это не календарь.
- Синхронизация: **односторонняя** запись в Google Tasks. Обратное чтение,
  разрешение конфликтов и обработка удалений на стороне Google не делаются.

### Таблетки
- Один курс, одно лекарство, **один приём в сутки в фиксированное время**.
- Дозы чередуются по циклу. Модель общая: список доз произвольной длины,
  повторяемый по кругу (`[100, 75]` — частный случай сценария владельца).
- **Индекс дозы вычисляется из даты, а не хранится счётчиком:**
  `doseIndex = daysBetween(startDate, today) mod doses.size`.
  Счётчик «следующая доза» разъезжается при пропуске, перезагрузке или ручной
  правке истории и приводит к неверной дозировке. Это архитектурное
  требование, а не деталь реализации.
- Уведомление: три кнопки — «Принял», «+15 мин», «+60 мин» (Android
  показывает максимум три). Полный набор отсрочек (5/10/15/30/60) — внутри
  приложения.
- Пропуск дозы — неприятно, но не критично. Следствие: обычные уведомления и
  `setExactAndAllowWhileIdle`; полноэкранные будильники, звук поверх
  беззвучного режима и эскалация не нужны.
- История: список «принял / пропустил» + отметка приёма задним числом.

### Список покупок
- Голосовое добавление, отметка «куплено», отдельный виджет.
- Общего доступа с другими телефонами нет.

### Разбор фраз
- Гибрид: сначала правила, при неудаче — LLM. Обе реализации за общим
  интерфейсом `PhraseParser`, взаимозаменяемы.
- LLM: Claude Haiku 4.5 (модель `claude-haiku-4-5-20251001`) прямым HTTP-вызовом.
- **API-ключ вводится пользователем в настройках приложения.** В коде,
  `local.properties` и репозитории ключей нет — ни при каких обстоятельствах.

## 3. Стек и архитектура

Один Gradle-модуль, пакеты по функциям.

```
UI (Compose)  →  ViewModel  →  Repository  →  Room DAO
                                          →  GoogleTasksApi (Retrofit)
Widget / Tile / Shortcut  →  VoiceCaptureActivity  →  PhraseParser  →  Repository
AlarmManager  →  BroadcastReceiver  →  NotificationManager
```

| Область | Решение |
|---|---|
| Язык / UI | Kotlin, Jetpack Compose, Material 3 |
| БД | Room |
| DI | Ручной `AppContainer` в `Application` (не Hilt) |
| Виджеты | Glance |
| Будильники | `AlarmManager.setExactAndAllowWhileIdle` + пересоздание по `BOOT_COMPLETED` |
| Фоновые задачи | WorkManager (синхронизация с ретраями) |
| Речь | `RecognizerIntent` (системный диалог распознавания) |
| Сеть / JSON | Retrofit + kotlinx.serialization |
| Google OAuth | Credential Manager + Authorization API, обращение к Tasks REST API напрямую |
| Настройки | DataStore (Preferences) |

Версии зафиксированы консервативно (AGP 8.7.3, Kotlin 2.0.21, Gradle 8.9,
compileSdk/targetSdk 35, minSdk 29). Причина: собрать проект локально в среде
ассистента невозможно (Maven-репозиторий Google недоступен из контейнера),
проверка идёт через GitHub Actions, поэтому заведомо совместимый набор версий
дороже свежести. Поднимать версии — на этапе 10 или когда Android Studio
предложит.

### Обоснование неочевидных выборов

- **Один модуль.** Многомодульность окупается скоростью сборки в команде; для
  соло-проекта это налог на конфигурацию Gradle. Разделение возможно позже.
- **Ручной DI вместо Hilt.** BroadcastReceiver'ы, Glance-виджеты и
  `TileService` получают зависимости из ручного контейнера тривиально, тогда
  как с Hilt в них регулярно возникают проблемы. Плюс отсутствие
  кодогенерации важно при первом знакомстве с Android. Переход на Hilt
  впоследствии — механическая работа.
- **Room, а не SQLDelight.** Больше документации и примеров.
- **Retrofit, а не `google-api-services-tasks`.** Официальная библиотека —
  тяжёлая Java-обёртка с блокирующими вызовами, неудобная на Android.
- **`setExactAndAllowWhileIdle`, а не `setAlarmClock`.** Последний надёжнее в
  Doze, но показывает иконку будильника в статус-баре и оправдан только при
  критичности пропуска дозы, которой здесь нет.

### Модель данных (черновик)

- `reminders` — id, title, dueAt, repeatRule, isDone, remoteTaskId, syncState, createdAt
- `shopping_items` — id, title, isChecked, position, createdAt, remoteTaskId
- `med_courses` — id, name, doses (список мг), timeOfDay, startDate, isActive
- `med_intakes` — id, courseId, scheduledAt, takenAt, status, doseMg, snoozeCount

Поля `remoteTaskId` / `syncState` закладываются с самого начала, даже до
реализации синхронизации, чтобы не мигрировать схему на этапе 8.

## 4. План разработки

Каждый этап даёт APK, который можно поставить на телефон и проверить руками.

| № | Этап | Критерий приёмки |
|---|---|---|
| 0 | Каркас: проект, Compose, Room, навигация, тема, строки RU/EN, CI собирает debug-APK | Приложение ставится, открывается, показывает три пустых раздела |
| 1 | Список покупок: БД, добавление, отметка «куплено», удаление | Работающий список с клавиатурным вводом |
| 2 | Голосовой конвейер: `VoiceCaptureActivity`, распознавание, разбор фразы, экран подтверждения | «Молоко, хлеб, яйца» голосом → элементы в списке |
| 3 | Виджет покупок (Glance): список, кнопка микрофона, тап = отметить | Виджет на домашнем экране, тап по микрофону → запись |
| 4 | Напоминания: модель, парсер дат на правилах, `AlarmManager`, уведомления, повторы, восстановление после перезагрузки | Уведомление приходит вовремя и переживает перезагрузку |
| 5 | Быстрые точки входа: плитка в шторке, App Shortcuts, виджет-кнопка напоминаний | Из шторки в микрофон одним тапом при заблокированном экране |
| 6 | Таблетки: курс, цикл доз, ежедневный будильник, уведомление с тремя кнопками, история, отметка задним числом | Полный цикл за пару дней: сработало → отложил → принял → в истории |
| 7 | Экран самодиагностики разрешений + тестовое уведомление через минуту | Видно, что не разрешено, и чинится на месте |
| 8 | Google Tasks: OAuth, синхронизация через WorkManager, экран настройки, обработка отзыва доступа | Напоминание видно в Google Tasks на компьютере |
| 9 | LLM-парсер: поле ключа в настройках, стратегия «правила → LLM» | Фраза, не осиленная правилами, разбирается корректно |
| 10 | Полировка: английская локализация, тёмная тема, экспорт истории, UX | — |

Естественные точки остановки: после этапа 3 (полезное приложение уже есть) и
после этапа 7 (всё работает локально, Google опционален).

## 5. Соглашения

### Код
- Kotlin official code style, 4 пробела, ktlint-совместимое форматирование.
- Пакеты по функциям: `feature/<name>/{ui,data,domain}`, общее — в `core/`.
- ViewModel отдаёт единый immutable `UiState` через `StateFlow`; события UI —
  через методы ViewModel, не через колбэки в composable.
- Composable-функции не обращаются к репозиториям и `Context` напрямую.
- Строки — только в ресурсах, хардкод текста в UI запрещён (двуязычность).
- Публичные точки входа (Activity, Receiver, Worker, Tile, Widget) —
  максимально тонкие: вытащить зависимости, вызвать репозиторий, выйти.

### Тесты
- Обязательны юнит-тесты на две вещи: **парсер фраз** и **вычисление индекса
  дозы**. Это чистая логика без Android, ломается тихо и стоит дорого.
- UI-тесты не пишем.

### Git
- Ветка разработки: `claude/android-voice-assistant-88u9na`.
- Один коммит — один законченный этап или одна осмысленная правка.
- Сообщения коммитов на английском, императив: `Add shopping list widget`.

### Безопасность
- В репозитории нет ключей, токенов и keystore-файлов.
- API-ключ Anthropic — только в DataStore, вводится пользователем.
- `local.properties`, `*.jks`, `*.keystore` — в `.gitignore`.
- Для OAuth нужен стабильный keystore: хранится локально у владельца, в git не
  попадает; SHA-1 отпечатки debug- и release-ключей регистрируются в Google
  Cloud Console.

## 6. Открытые вопросы

- Название и package (`com.zhukoffsky.magpie`) — подтверждается владельцем.
  Менять после этапа 0 дорого.
- `minSdk` / `targetSdk` — определяются на этапе 0 по актуальным версиям
  (ориентир: `minSdk 29`).
- Настройка Google Cloud Console (проект, включение Tasks API, OAuth-экран,
  SHA-1) выполняется владельцем перед этапом 8 — доступа к консоли у
  ассистента нет.
- Экран подтверждения после диктовки может быть упрощён до
  самозакрывающейся карточки, если полная форма окажется медленной.

## 7. Как собирать

```bash
./gradlew assembleDebug      # APK в app/build/outputs/apk/debug/
./gradlew test               # юнит-тесты
```

Сборка в среде ассистента невозможна: Maven-репозиторий Google (`dl.google.com`)
закрыт сетевой политикой контейнера. Проверка изменений идёт через GitHub
Actions (`.github/workflows/build.yml`), APK доступен артефактом сборки.

## 8. Проверка на устройстве (накапливается)

Собрать APK в среде ассистента невозможно, эмулятора нет, поэтому всё ниже
проверяется владельцем вручную. Список пополняется каждым этапом; сверка —
в конце, перед остановкой на этапе 7.

### Этап 0 — каркас
- [ ] APK ставится на Pixel 8 и открывается.
- [ ] Иконка на домашнем экране выглядит прилично (адаптивная, тёмная тема).
- [ ] Переключение трёх вкладок работает, состояние вкладки не теряется.
- [ ] Смена языка системы на английский переключает интерфейс и название.

### Этап 1 — список покупок
- [ ] Добавление с клавиатуры, Enter добавляет и не закрывает клавиатуру.
- [ ] Чекбокс зачёркивает позицию, счётчик купленного считает верно.
- [ ] Свайп удаляет позицию; «Убрать купленное» удаляет только отмеченные.
- [ ] Пустое состояние показывается на пустом списке.

### Этап 2 — голосовой ввод
- [ ] Тап по микрофону открывает распознавание **без** запроса разрешений.
- [ ] «Молоко, хлеб и яйца» → три отдельных поля в карточке подтверждения.
- [ ] Правка и удаление позиции в карточке работают, «Сохранить» пишет в список.
- [ ] Отмена распознавания даёт сообщение с «Повторить», а не тихое закрытие.
- [ ] Экран за карточкой виден (активность прозрачная); приложение не
      появляется дважды в списке недавних.
- [ ] **Открытый вопрос:** ставит ли Google-распознавание запятые в русской
      речи. Если нет — разделение по союзу «и» остаётся единственным рабочим
      правилом и парсер надо доучивать.

### Этап 8 — Google Tasks
**Проверяется только на локальной сборке из Android Studio.** APK из CI
подписан ключом, который раннер генерирует заново каждый запуск, поэтому его
SHA-1 не совпадает с зарегистрированным и авторизация не пройдёт. Настройка
описана в `docs/google-tasks-setup.md`.

- [ ] Google Cloud Console настроен по инструкции, SHA-1 debug-ключа
      зарегистрирован.
- [ ] «Подключить Google Tasks» открывает выбор аккаунта и экран согласия.
- [ ] Новое напоминание появляется на tasks.google.com.
- [ ] Отметка «выполнено» в приложении перекрашивает задачу в Google.
- [ ] Удаление напоминания удаляет задачу в Google.
- [ ] Напоминания, созданные **до** подключения, тоже выгружаются.
- [ ] В самолётном режиме синхронизация не падает, а повторяется позже.
- [ ] Отзыв доступа в настройках Google-аккаунта показывает ошибку в
      настройках приложения, а не тихо ломает выгрузку.

### Этап 7 — самодиагностика
- [ ] Вкладка «Настройки» показывает шесть проверок, состояние совпадает с
      реальными настройками телефона.
- [ ] Кнопка «Исправить» открывает нужный системный экран для каждой из них.
- [ ] После возврата из настроек список сам обновляется, без перезапуска.
- [ ] Тестовое уведомление приходит через минуту при заблокированном экране.
- [ ] Если выключить канал «Напоминания» в системе — проверка это ловит.

### Этап 6 — таблетки
- [ ] Курс заводится: название, «100, 75», время, дата начала. Сегодняшняя
      доза на карточке совпадает с ожидаемой.
- [ ] Уведомление приходит в назначенное время и показывает три кнопки:
      «Принял», «+15 мин», «+60 мин».
- [ ] «+15 мин» откладывает и не ломает будильник на завтра.
- [ ] «Принял» закрывает уведомление, карточка и история обновляются.
- [ ] Полный набор отсрочек (5/10/15/30/60) работает на экране приложения.
- [ ] Пропущенный день виден в истории как «пропущено» и отмечается задним
      числом — с дозой того дня, а не сегодняшней.
- [ ] Проверка за два дня подряд: доза чередуется 100 → 75.
- [ ] После перезагрузки телефона будильник приёма восстанавливается.
- [ ] **Известное ограничение:** время и дата вводятся текстом, пикеров нет.
      Дата начала задаёт фазу цикла — ошибка в ней даёт неверную дозу.

### Этап 5 — быстрые точки входа
- [ ] Плитки «Напоминание» и «Покупка» добавляются в шторку и ведут прямо
      в распознавание.
- [ ] С заблокированного экрана плитка сначала просит разблокировать —
      это ожидаемо, распознавание поверх лока не работает.
- [ ] Долгий тап по иконке приложения показывает два шортката, оба
      открывают нужный тип записи.
- [ ] Виджет-кнопка напоминаний ставится на домашний экран и работает.
- [ ] Запуск покупки, когда экран диктовки напоминания ещё открыт (и
      наоборот), переключает тип, а не молча оставляет старый.

### Этап 4 — напоминания
- [ ] «завтра в 9 позвонить в поликлинику» с клавиатуры и голосом даёт
      одинаковый результат: заголовок без слов о времени, время верное.
- [ ] Уведомление приходит в назначенное время, в том числе когда телефон
      лежал в Doze (проверить на ночном напоминании).
- [ ] Кнопка «Готово» в уведомлении закрывает его и отмечает напоминание.
- [ ] Повторяющееся («каждый вторник») после срабатывания само переезжает на
      следующую неделю.
- [ ] После перезагрузки телефона будущие напоминания продолжают работать.
- [ ] Разрешение на уведомления запрашивается при первом запуске.
- [ ] Точные будильники: проверить, что система выдала разрешение сама
      (Настройки → Приложения → Сорока → Будильники и напоминания).
- [ ] **Известное ограничение:** время в карточке подтверждения не
      редактируется — только заголовок. Если парсер ошибся, напоминание
      придётся удалить и завести заново. Редактирование — этап 10.

### Этап 3 — виджет покупок
- [ ] Виджет добавляется на домашний экран и показывает актуальный список.
- [ ] Тап по позиции отмечает её купленной, изменение видно и в приложении.
- [ ] Изменение списка в приложении обновляет виджет без ручного обновления.
- [ ] Кнопка микрофона на виджете ведёт сразу в распознавание.
- [ ] Виджет переживает перезагрузку телефона.

## 9. Текущий статус

**Этап 0 выполнен:** каркас проекта, Compose + Material 3, Room со схемой всех
четырёх таблиц, нижняя навигация по трём разделам, локализация RU/EN,
адаптивная иконка, CI с юнит-тестами и debug-APK.

**Этап 1 выполнен:** список покупок — ввод с клавиатуры, отметка «куплено»,
удаление свайпом, массовое удаление купленного, пустое состояние.
Слои: `ShoppingRepository` → `ShoppingViewModel` → `ShoppingScreen`.

**Этап 2 выполнен:** голосовой ввод. `VoiceCaptureActivity` — прозрачная
активность в отдельной задаче, сразу открывает системный диалог распознавания;
`ShoppingPhraseParser` режет фразу на позиции по запятым и союзам; экран
подтверждения с правкой и удалением позиций. Кнопка микрофона на экране
покупок. Точка входа задаёт тип записи через `VoiceTarget`.

**Этап 3 выполнен:** виджет покупок на Glance. Читает тот же поток Room, что и
экран, поэтому обновляется сам — `updatePeriodMillis` нулевой, периодических
пробуждений нет. Тап по позиции отмечает купленной через `ActionCallback`,
кнопка микрофона ведёт в `VoiceCaptureActivity`.

**Этап 4 выполнен:** напоминания. `ReminderPhraseParser` разбирает даты,
время и повторы на правилах; `AlarmManager.setExactAndAllowWhileIdle` через
интерфейс `ReminderScheduler` (Android-реализация подменяется в тестах);
уведомление с кнопкой «Готово»; пересоздание будильников по `BOOT_COMPLETED`
и `MY_PACKAGE_REPLACED`. Голосовой ввод напоминаний через тот же
`VoiceCaptureActivity` с `VoiceTarget.REMINDER`.

Взято разрешение `USE_EXACT_ALARM` (выдаётся системой без участия
пользователя). Play его разрешает только будильникам и календарям, но
приложение в Play не публикуется — иначе пришлось бы каждый раз ходить в
системные настройки за `SCHEDULE_EXACT_ALARM`.

**Этап 5 выполнен:** быстрые точки входа. Две плитки в шторке
(`TileService`), два статических шортката, виджет-кнопка напоминаний.
Цель различается по intent-action (`…action.CAPTURE_SHOPPING` /
`CAPTURE_REMINDER`), а не по extra: шорткаты так надёжнее. Из-за шорткатов
`VoiceCaptureActivity` пришлось сделать `exported="true"`.

**Этап 6 выполнен:** таблетки. `DoseCycle` вычисляет дозу из даты (тесты
обязательны и написаны), `MedRepository` ведёт курс, приёмы и историю,
`AlarmManagerMedScheduler` держит два раздельных будильника — ежедневный и
отложенный, чтобы отсрочка не затирала завтрашний. Уведомление с тремя
кнопками, полный набор отсрочек внутри приложения, история с отметкой задним
числом.

Каркас истории строится из цикла доз, а не из записей БД: проигнорированный
день записи не создаёт и без каркаса просто исчез бы из истории.

**Этап 7 выполнен:** вкладка «Настройки» с самодиагностикой. Шесть проверок
(уведомления, два канала по отдельности, точные будильники, оптимизация
батареи, наличие распознавателя), кнопка «Исправить» открывает нужный
системный экран, список перечитывается при каждом возврате на экран.
Тестовое уведомление через минуту идёт тем же путём, что и настоящее:
точный будильник → пробуждение из Doze → показ.

Разделов в нижней навигации стало четыре. Сюда же лягут настройки Google
(этап 8) и поле API-ключа (этап 9).

**Этап 8 выполнен:** односторонняя выгрузка напоминаний в Google Tasks.
Авторизация через Authorization API (Play Services), обращение к REST API
напрямую через Retrofit, выгрузка в `SyncWorker` (WorkManager, повтор с
backoff), настройки и статус на вкладке «Настройки».

Ключей в коде нет: Android-клиент OAuth определяется парой «пакет + SHA-1».
Отсюда ограничение — APK из CI авторизацию не проходит, синхронизация
проверяется только на локальной сборке. Инструкция по настройке Google Cloud
Console: `docs/google-tasks-setup.md`.

Google Tasks хранит только дату, время задачи отбрасывается на их стороне.
Само напоминание в приложении срабатывает в точное время.

**Следующий — этап 9:** LLM-парсер (поле ключа в настройках, стратегия
«правила → LLM»).
