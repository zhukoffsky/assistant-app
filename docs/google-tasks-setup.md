# Подключение Google Tasks

Выполняется владельцем один раз. Доступа к Google Cloud Console у ассистента
нет, поэтому эти шаги автоматизировать нельзя.

## 1. Проект и API

1. Открыть [Google Cloud Console](https://console.cloud.google.com/).
2. Создать проект (например, `magpie`).
3. **APIs & Services → Library** → найти **Google Tasks API** → **Enable**.

## 2. Экран согласия OAuth

**APIs & Services → OAuth consent screen**:

- Тип: **External** (Internal доступен только для Google Workspace).
- Заполнить название приложения, почту поддержки и почту разработчика.
- Scopes: добавить `https://www.googleapis.com/auth/tasks`.
- Test users: добавить **свой аккаунт Google** и аккаунты членов семьи,
  которым раздашь APK.

Публиковать приложение не нужно: в режиме **Testing** доступ работает для
тестовых пользователей бессрочно. Ограничение — не больше 100 таких
аккаунтов, чего для семьи заведомо хватает.

## 3. OAuth-клиент для Android

**APIs & Services → Credentials → Create Credentials → OAuth client ID**:

- Application type: **Android**
- Package name: `com.zhukoffsky.magpie`
- SHA-1: отпечаток ключа, которым подписан APK (см. ниже).

Идентификатор клиента никуда вписывать не надо: Android-клиент определяется
парой «имя пакета + SHA-1». Именно поэтому в коде и в репозитории нет ни
одного секрета.

## 4. SHA-1 — где взять и почему это важно

Отпечаток debug-ключа Android Studio:

```bash
keytool -list -v -alias androiddebugkey \
  -keystore ~/.android/debug.keystore \
  -storepass android -keypass android
```

На Windows keystore лежит в `%USERPROFILE%\.android\debug.keystore`.

**Главное следствие:** авторизация привязана к конкретному ключу подписи.

- APK, собранный **локально** в Android Studio, подписан твоим
  debug-ключом → работает после регистрации его SHA-1.
- APK из **GitHub Actions** подписан ключом, который раннер генерирует
  заново на каждом запуске → SHA-1 каждый раз новый → авторизация в Google
  **никогда не пройдёт**.

Поэтому синхронизацию проверяем только на локальной сборке. Всё остальное в
приложении на APK из CI работает как обычно.

Если позже захочется получать из CI APK, пригодный для синхронизации, —
завести отдельный release-keystore, положить его в GitHub Secrets в base64,
подписывать им сборку и зарегистрировать его SHA-1 вторым OAuth-клиентом.
Сам файл keystore в репозиторий не попадает ни при каком варианте.

## 5. Проверка

1. Собрать и поставить APK из Android Studio.
2. Настройки → **Подключить Google Tasks** → выбрать аккаунт, дать доступ.
3. Создать напоминание.
4. Открыть [tasks.google.com](https://tasks.google.com) на компьютере —
   задача должна появиться в списке «Мои задачи».

## Что синхронизация делает и чего не делает

- Выгружает напоминания: создание, изменение статуса, удаление.
- Google Tasks хранит **только дату**, время задачи он отбрасывает. В
  приложении напоминание всё равно сработает в точное время — в Tasks оно
  выглядит как задача на день.
- Обратное чтение не делается. Задача, отмеченная выполненной в Google, в
  приложении останется активной. Это осознанное решение: двусторонняя
  синхронизация требует разрешения конфликтов и обработки удалений-призраков.
- Список покупок не синхронизируется.
